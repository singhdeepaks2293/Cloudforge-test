# CloudForge v2 — Service Catalog

> **Audit date:** 2026-11-22 IST · **Source:** Phase 0 audit of all 248 files.
> Status and fidelity are assigned from what the **code actually does**
> (backend route + adapter/simulator + frontend page + tests), never from
> what docs or the registry claim. See `docs/SERVICE_FIDELITY.md` for the
> fidelity definitions and the evidence per service.
>
> **Fidelity key:** `REAL` / `API_EMULATED` / `SIMULATED` / `PARTIAL` /
> `UNSUPPORTED` (definitions in `SERVICE_FIDELITY.md`).
> **Status key:** `implemented` / `partial` / `registry-only` /
> `not started`.
>
> **AWS-duplicate UI rule (user decision 2026-11-22):** every service gets a
> console mirroring the real AWS console's layout, navigation, tables, detail
> tabs, wizards and action names/placement, in CloudForge branding only (no
> AWS logos/trademarks/proprietary icons/copied assets; never claim it is
> AWS). The **Mirrors** column records which real AWS console screens /
> workflows each CloudForge console mirrors; **Differs** records deliberate
> differences (fidelity + branding + local limits). A generic list page does
> NOT count as a service console. Unsupported operations must be labelled
> and disabled, never shown as working.
>
> **Phase 1 (2026-11-22):** the global console is now registry-driven
> (`GET /api/v1/services`, 86 services) and dedicated consoles exist for
> **EC2, S3, VPC and IAM** (see their rows — each records what it mirrors
> and what it deliberately differs on, including which actions are
> disabled and why), plus a generic service console for every other
> registry service and a **Resource Explorer** (`/explorer`, implemented,
> REAL backend data only). All other rows below are unchanged from the
> Phase 0 audit.
>
> **Phase 3 (2026-11-22):** dedicated consoles now exist for **DynamoDB,
> RDS, ElastiCache, ELB, Route 53, SQS, SNS, EventBridge, Lambda and API
> Gateway** (see their rows). All ten are real implementations with HTTP
> routes — none is registry-only any more.
